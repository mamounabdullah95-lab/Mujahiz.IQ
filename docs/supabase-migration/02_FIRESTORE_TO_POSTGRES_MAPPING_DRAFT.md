# Firestore-to-PostgreSQL mapping draft

## Status and conventions

- **[Future plan]** This is a logical first pass, not executable SQL. No schema, migration, policy, trigger, function, or table was created.
- **[Verified current fact]** Current shapes come from `src/types/domain.ts`, `src/types/workspace.ts`, `src/services/`, `functions/src/`, `firestore.rbac.rules`, and the live collection inventory in `00_CURRENT_STATE_AND_INVENTORY.md`.
- **[Future plan]** Default identifiers are internal UUIDs unless a deterministic text key is operationally safer. Every migrated entity retains a unique `firebase_legacy_id` or equivalent source-specific field.
- **[Future plan]** Firebase UID is stored as bounded text, not coerced to UUID. Identity mapping must support a later Supabase Auth identity without losing Firebase UID.
- **[Future plan]** `created_at`/`updated_at` use timezone-aware timestamps. Firestore server timestamps require an explicit conversion report for null, pending, string, Date, and Timestamp variants.
- **[Future plan]** Flexible historical payloads may be retained in restricted `jsonb` snapshots for audit, but searchable relationships and authorization fields must be normalized.
- **[Future plan]** “Trusted-only” means browser roles receive no direct write grant; changes occur through reviewed SQL/RPC functions, Edge Functions, or an application service inside a database transaction.

- **[Verified current fact]** Current first submission creates quotation, V1 revision, response event, and Buyer notification atomically. Current updates use a transaction, compare material commercial fields, allocate the next deterministic revision/event/notification, and treat identical resubmission as a no-op. Sources: `src/services/workspace.ts`, `src/utils/rfqLifecycle.ts`, and RFQ Emulator tests.
- **[Future plan]** The PostgreSQL command boundary must recreate that entire invariant; direct writes to `quotations` or revision tables are not acceptable.

## Migration transformation rules

1. **[Future plan]** Export a bounded, approved snapshot with source commit/deployment/rules/index metadata and collection counts; never use application reads as an implicit export.
2. **[Future plan]** Preserve every Firestore document ID in a unique legacy column before creating relationships.
3. **[Future plan]** Convert references in a second deterministic pass and fail on orphan, ambiguity, or two-sided ownership mismatch.
4. **[Future plan]** Explode arrays into relation tables where they affect authorization, uniqueness, querying, or referential integrity; retain ordered snapshots where audit fidelity requires it.
5. **[Future plan]** Recompute normalized fields and fingerprints with a versioned algorithm, compare to legacy values, and quarantine differences for review rather than overwriting silently.
6. **[Future plan]** Verify immutable revisions/events/audits by counts, unique legacy IDs, per-aggregate sequences, and deterministic hashes.
7. **[Future plan]** Keep imported Production rows read-only until mapping, constraints, RLS, and reconciliation tests pass in rehearsal.
